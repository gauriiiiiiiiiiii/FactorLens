FACTORLENS

PROBLEM TYPE: Regression (predict next-period returns) + Time-series factor backtesting

TECH STACK: Python, pandas, numpy, scikit-learn, xgboost, plotly, Streamlit

1) PROBLEM STATEMENT
- We want to learn return-driving equity factors from historical price and fundamentals data, then validate those signals with both ML prediction quality and long-short factor returns.
- The core task is predicting next-period returns at the stock level (regression), while also constructing factor portfolios to test if signals have economically meaningful performance.

What is the problem in one sentence?
- Build a repeatable ML pipeline that transforms raw prices + fundamentals into factor signals, predicts next-period returns, and validates those signals via long-short backtests and exposure analysis.

Why is it important?
- Traditional factor investing uses fixed definitions (value, momentum, quality, etc.) that might be regime dependent.
- A data-driven, modular pipeline makes factor research repeatable, measurable, and explainable.
- It allows an analyst to compare models, interpret factor importance, and see whether a factor actually delivers a positive long-short return.

Real-world applications
- Systematic equity research and strategy prototyping
- Portfolio risk explanation (factor exposure)
- Regime monitoring and signal health checks
- Rapid experimentation via a UI for non-engineering stakeholders

1A) STEP-BY-STEP PROCEDURE TO BUILD THIS PROJECT
Step 0: Define scope and pipeline goals
- Decide the task: return prediction + factor research, not just classification.
- Define outputs: factor returns, model metrics, backtest curve, and portfolio exposure.

Step 1: Collect data
- Choose datasets with price and fundamentals coverage (Kaggle CSVs).
- Ensure raw files are separated into prices and fundamentals folders.

Step 2: Normalize schemas and load data
- Normalize column names (case, spaces, hyphens) into canonical names.
- Map messy column names to standard fields (date, ticker, close, market_cap, etc.).
- Infer ticker from filename if missing in price CSVs.
- Infer date from filename year if missing in fundamentals.

Step 3: Compute price returns
- Sort prices by ticker and date.
- Compute per-ticker percent change (return) from close prices.

Step 4: Merge fundamentals with prices
- Sort both datasets by ticker and date.
- Use backward as-of merge so each price row only sees fundamentals available at or before that date.

Step 5: Engineer factor features
- Compute momentum, volatility, size, value, profitability, growth, quality, earnings_yield, leverage, liquidity.
- Build return_next as the forward target variable.
- Drop rows missing any available feature or target.

Step 6: Construct factor portfolios
- For each date and feature, rank stocks and create a long-short return (top quantile minus bottom quantile).
- Aggregate per feature into a factor_returns table.

Step 7: Train models
- Split data into train/test by time order.
- Train LASSO, Random Forest, and XGBoost.
- Extract predictions and feature importance.

Step 8: Backtest model predictions
- Sort predicted returns per date into quantiles.
- Build long-short daily returns and cumulative performance.

Step 9: Compute portfolio exposure
- Take latest factor values per ticker.
- Multiply by user portfolio weights to estimate factor exposures.

Step 10: Visualize and deploy
- Build Streamlit UI with tabs for overview, factors, model, backtest, exposure.
- Add plots for cumulative factor returns, correlations, and model comparison.

Step 11: Save processed data
- Persist stock_features.csv and factor_returns.csv for demo mode.

2) DATASET UNDERSTANDING
Source of dataset
- Raw CSVs (prices + fundamentals) from Kaggle datasets, loaded via a structured loader.
- A demo mode uses preprocessed CSVs (stock_features.csv and factor_returns.csv).

Datasets used (raw)
- Prices: jacksoncrow/stock-market-dataset (daily OHLCV with ticker).
- Fundamentals: cnic92/200-financial-indicators-of-us-stocks (company financials).

Key raw price fields (typical)
- date, open, high, low, close, adj_close, volume, ticker

Key raw fundamentals fields (typical)
- ticker, report_date or fiscal_date, market_cap, book_value, pe_ratio, pb_ratio,
  revenue, net_income, total_assets, shares_outstanding

Features and target variable
- Target: return_next (next-period return per ticker). Computed by shifting the per-ticker return series forward one step.
- Features (13 factors):
  - momentum_12m, momentum_6m, momentum_3m
  - volatility_3m, volatility_1m
  - size (log market cap)
  - value (book_value / market_cap)
  - profitability (net_income / total_assets)
  - growth (revenue YoY)
  - quality (net_income / revenue)
  - earnings_yield (1 / PE ratio)
  - leverage (total_assets / market_cap)
  - liquidity (rolling avg volume, log-scaled)

Data size
- Depends on the number of tickers and years loaded. The app exposes a max_tickers slider to bound size.
- The raw CSV universe can be large, but demo mode uses processed data for fast runs.

Data types
- Numerical: prices, returns, fundamentals, engineered factors
- Categorical: ticker
- Datetime: date
- No text or image data

Data imbalance
- Not a classification task, so class imbalance does not apply.
- Return distribution is typically heavy-tailed and noisy, which makes regression challenging and motivates robust evaluation.

3) DATA PREPROCESSING
Handling missing values
- Missing required columns in CSVs are detected and surfaced as errors.
- Feature engineering drops rows where any available feature or return_next is missing.
- Before modeling, NaN and infinite values are replaced with 0 to avoid model failures.

Encoding categorical variables
- Ticker is not used directly as a feature; it only groups time series for return and rolling computations.

Feature scaling
- LASSO uses StandardScaler for normalized inputs.
- Tree-based models (Random Forest, XGBoost) operate on raw numeric values.

Outlier detection
- No explicit outlier removal. This is an intentional trade-off for simplicity.
- Robustness is partially handled via quantile long-short portfolios and model regularization.

Data cleaning steps
- Column normalization: unify messy CSV headers into canonical names.
- Ticker inference: if missing in price files, infer from filename stem.
- Date inference: if fundamentals file lacks date, infer from filename year.
- As-of merge: align fundamentals to price data using backward merge to prevent look-ahead bias.

5) FEATURE ENGINEERING
New features created
- Momentum features from price changes over 3/6/12 months.
- Volatility features from rolling std of returns.
- Market cap inferred if missing (price * shares outstanding).
- Value/profitability/quality/growth ratios from fundamentals.
- Earnings yield from PE ratio.
- Leverage from assets and market cap.
- Liquidity from rolling volume.
- return_next as supervised target.

Feature selection techniques
- available_features filters features with actual data presence.
- This prevents training on empty or fully-null signals.

Dimensionality reduction
- Not used currently. PCA or factor analysis could be added to reduce collinearity.

6) MODEL SELECTION
Models tried
- LASSO regression (sparse linear baseline)
- Random Forest (non-linear bagging model)
- XGBoost (boosted trees for strong tabular performance)

Why these models
- LASSO is interpretable and highlights a compact set of signals.
- RF captures non-linear relationships without heavy preprocessing.
- XGBoost often performs best on tabular data with strong regularization controls.

Baseline model
- LASSO, due to interpretability and its ability to handle multicollinearity via L1 penalty.

7) TRAINING PROCESS
Train-test split
- Time-ordered 80/20 split with shuffle=False to reduce look-ahead.
- This is crucial in finance to avoid future leakage.

Cross-validation
- LASSO internally uses CV (LassoCV) on the training slice.
- Full time-series CV is not used yet but is a planned improvement.

Hyperparameter tuning
- Hyperparameters are currently set manually for RF and XGBoost.
- For interview depth, propose RandomizedSearchCV with TimeSeriesSplit.

Full hyperparameter rationale per model (why each value)
LASSO (LassoCV)
- cv=5: balances bias/variance and runtime; enough folds to stabilize alpha selection.
- random_state=7: reproducibility for CV path selection.
- max_iter=10000: ensures convergence when features are correlated or scaled.
- StandardScaler used before LASSO because L1 penalties are scale-sensitive.

Random Forest
- n_estimators=400: reduces variance and stabilizes feature importance; more trees smooth noise.
- max_depth=8: limits tree complexity to avoid overfitting noisy returns.
- min_samples_leaf=3: enforces minimum leaf size for smoother splits.
- min_samples_split=6: prevents very small splits that overfit.
- max_features="sqrt": standard choice for regression forests; reduces correlation among trees.
- random_state=7: reproducibility of bootstrap and splits.
- n_jobs=-1: parallel training to reduce runtime on multi-core CPUs.

XGBoost
- n_estimators=500: enough boosting rounds to learn signal with small learning rate.
- learning_rate=0.05: conservative step size to reduce overfitting.
- max_depth=5: moderate depth for non-linear patterns without extreme variance.
- subsample=0.85: row subsampling adds regularization and robustness.
- colsample_bytree=0.85: feature subsampling reduces feature dominance and overfit.
- reg_alpha=0.1: L1 regularization to encourage sparsity in splits.
- reg_lambda=1.0: L2 regularization to shrink weights and reduce overfit.
- random_state=7: reproducibility.
- n_jobs=-1: parallelism for faster training.

Overfitting and underfitting handling
- LASSO regularization reduces variance.
- RF/XGBoost use depth and leaf constraints.
- Time-ordered validation acts as a realistic generalization test.

8) EVALUATION METRICS
Metrics used
- MSE: measures prediction error magnitude.
- R2: shows variance explained by model.
- Sharpe (annualized) for strategy risk-adjusted return.
- Total cumulative return from long-short backtest.

Why these metrics
- MSE and R2 are standard for regression and capture statistical predictive power.
- Sharpe and cumulative return capture economic significance.

Confusion matrix
- Not applicable because the target is continuous.
- If reframed as classification (up/down), confusion matrix and ROC-AUC could be used.

15) INTERVIEW TALK TRACK 
FactorLens is a Streamlit-based factor research pipeline that ingests raw equity prices and fundamentals, normalizes schemas, and merges fundamentals to prices using a backward as-of join to avoid look-ahead bias. It engineers 13 standard factor signals, builds long-short factor returns for each signal, and trains ML models (LASSO, Random Forest, XGBoost) to predict next-period returns on a time-ordered split. The app compares models by MSE and R2, and then validates economic relevance with a long-short backtest and Sharpe ratio. It also computes portfolio factor exposure for user-selected tickers. The system is modular, reproducible, and designed for rapid research iteration.

16) LIMITATIONS AND ASSUMPTIONS
- No transaction costs or slippage in backtest.
- No walk-forward CV; single time-ordered split.
- Fundamentals assumed available at report date (no reporting delay).
- Data quality depends on upstream CSV accuracy.

21) FINANCIAL TERMS AND FEATURES
Below are the key finance terms used in this project. Each term is defined with intuition and how it appears in the pipeline.

Return
- Percentage change in price from one period to the next. Used as the base signal for prediction.

Return_next
- Forward return used as the supervised target. It is return shifted by one period.

Factor
- A systematic characteristic (e.g., value, momentum) that explains cross-sectional differences in returns.

Momentum
- Measures the tendency for assets that performed well in the recent past to continue performing well.
- Implemented as trailing return over 3, 6, and 12 months.

Volatility
- Measures variability of returns. Higher volatility means more risk/uncertainty.
- Implemented as rolling standard deviation of returns (1m and 3m).

Size
- Proxy for company scale. Typically smaller firms outperform in some regimes.
- Implemented as log of market cap.

Market cap
- Price times shares outstanding. Represents company size in equity markets.

Value
- Cheapness of a stock. Often measured by book-to-market.
- Implemented as book_value / market_cap.

Book value
- Accounting value of equity (assets minus liabilities). Used for value signals.

Profitability
- Efficiency of converting assets into earnings.
- Implemented as net_income / total_assets.

Quality
- Profitability relative to revenue, indicating margin strength.
- Implemented as net_income / revenue.

Growth
- Expansion of company fundamentals over time.
- Implemented as year-over-year revenue growth.

Earnings yield
- Inverse of PE ratio. Higher yield implies cheaper earnings.
- Implemented as 1 / pe_ratio.

PE ratio
- Price to earnings ratio. Higher PE implies more expensive valuation.

Leverage
- Balance sheet risk. High leverage can increase risk and return sensitivity.
- Implemented as total_assets / market_cap.

Liquidity
- Ease of trading without moving the price. Higher liquidity is generally preferred.
- Implemented as log of rolling average volume.

Long-short portfolio
- Long top-ranked assets and short bottom-ranked assets to isolate factor effects.

Factor return
- The daily return of a long-short portfolio formed by a single factor.

Sharpe ratio
- Risk-adjusted return. Higher Sharpe means more return per unit of volatility.

Regime
- Market condition classification (risk-on, risk-off, mixed) based on rolling mean and volatility of market returns.

As-of merge
- Time-aligned join using the most recent fundamentals available at or before each price date.
